|------|---------|---------|

| 呼兰河传 | ["其他"] | ["文学"] |
| 背影 | ["其他"] | ["文学"] |

| The Lord of the Rings | ["其他"] | ["文学"] |

**根因**：纯关键词计数方式对短文本（书名+简介）匹配能力弱，很多经典作品因为简介中不含特定关键词而被漏标。

### 1.4 算法层面的根本缺陷

| 缺陷 | 说明 |
|------|------|
| **无关键词权重** | "Python"和"系统"权重相同，但前者是强指示词，后者是弱指示词 |
| **无TF-IDF加权** | 高频泛化词（"系统"、"分析"）和低频专有词（"Python"、"量子物理"）得分相同 |
| **无置信度阈值** | 只要某领域得分>0就会被选上，哪怕只匹配了1个泛化词 |
| **无领域排他性** | 不同领域的关键词列表有大量重叠（"思想"同时出现在哲学和社会科学） |
| **无书名特殊处理** | 书名是最强的领域指示信号，但和简介等权混合 |
| **英文文本处理弱** | 英文书名和简介几乎无法匹配中文关键词 |

## 二、优化方案设计

### 2.1 关键词体系重构

#### 2.1.1 三级关键词分层

将每个领域的关键词分为三个等级：

| 等级 | 含义 | 权重 | 示例（计算机科学） |
|------|------|------|-------------------|
| **核心词** | 该领域独有，几乎不可能出现在其他领域 | 5.0 | Python, Java, Docker, Kubernetes, API, SDK, React, Vue |
| **特征词** | 该领域常用，偶尔出现在其他领域 | 2.0 | 编程, 算法, 数据结构, 软件工程, 机器学习 |
| **泛化词** | 多领域共用，仅作辅助参考 | 0.5 | 系统, 技术, 分析, 数据, 应用, 平台 |

#### 2.1.2 泛化词清理

从所有领域的关键词列表中移除以下**跨领域污染词**，或将其降级为泛化词（权重0.5）：

**计算机科学需清理的词**：
- 移除：系统、技术、科技、智能、自动化、平台、框架、应用、电子、程序、数码
- 降级为泛化词：数据、分析、网络

**生活健康需清理的词**：
- 移除：生活、情感、成长、健康（太泛化）
- 保留具体词：养生、健身、瑜伽、菜谱、育儿

**社会科学需清理的词**：
- 移除：思想（与哲学重叠）、近代史/现代史/当代史（与历史文化重叠）

**哲学需清理的词**：
- 移除：思想（太泛化）、人文（太泛化）

**心理学需清理的词**：
- 移除：情绪、思维、人际关系（太泛化，文学作品大量使用）

#### 2.1.3 新增"数学"领域

当前"自然科学"包含了数学，但数学与经济学、计算机科学有密切关联，建议独立：

```json
{
  "domain": "数学",
  "keywords": {
    "core": ["微积分", "线性代数", "概率论", "数理统计", "拓扑学", "数论", "微分方程", "博弈论", "Game Theory"],
    "feature": ["数学分析", "代数", "几何", "应用数学", "纯数学", "数学建模"],
    "general": ["证明", "定理", "公式"]
  }
}
```

### 2.2 评分算法优化

#### 2.2.1 加权关键词匹配

```
旧算法：score = Σ count(keyword_i)

新算法：score = Σ (weight_level(keyword_i) × count(keyword_i))
        其中 weight_level(core)=5.0, weight_level(feature)=2.0, weight_level(general)=0.5
```

#### 2.2.2 TF-IDF加权

```
IDF(keyword) = log(N / df(keyword))
其中 N=总书籍数, df(keyword)=包含该关键词的书籍数

最终得分：score = Σ (weight_level(keyword_i) × IDF(keyword_i) × count(keyword_i))
```

这样"Python"（只出现在少数计算机书中）的IDF远高于"系统"（出现在大量书中），自动抑制泛化词。

#### 2.2.3 书名加权

书名是最强的领域指示信号，应给予更高权重：

```
combined_text = 3.0 × title + 1.0 × book_intro + 0.5 × author_intro
```

#### 2.2.4 置信度阈值

只有当某领域的**加权得分**超过阈值时才分配该标签：

```
threshold = max(5.0, 0.3 × 最高得分领域的得分)

规则：
- 如果某领域得分 < threshold，则不分配该标签
- 如果所有领域得分 < 3.0，则标记为"其他"
```

#### 2.2.5 领域排他性检查

当一本书被分配了两个差异极大的领域标签时（如"计算机科学"+"文学"），进行合理性检查：

```
如果两个标签的得分比 < 0.3（即第二标签得分不到第一标签的30%）
  则只保留第一标签，不分配第二标签
```

### 2.3 英文书籍处理

#### 2.3.1 英文关键词补充

为每个领域添加英文核心关键词：

```json
{
  "domain": "计算机科学",
  "keywords": {
    "core_en": ["programming", "algorithm", "software", "database", "machine learning", "deep learning", "neural network", "Python", "Java", "API", "SDK", "Docker", "Kubernetes", "React", "Vue"]
  }
}
```

#### 2.3.2 英文文本不参与中文匹配

当检测到文本主要为英文时，只使用英文关键词进行匹配。

### 2.4 书名硬匹配规则

为知名经典作品建立书名→领域标签的硬匹配表：

```json
{
  "红楼梦": ["文学", "历史文化"],
  "三国演义": ["文学", "历史文化"],
  "西游记": ["文学", "历史文化"],
  "水浒传": ["文学", "历史文化"],
  "战争与和平": ["文学", "历史文化"],
  "百年孤独": ["文学"],
  "傲慢与偏见": ["文学"],
  "呼兰河传": ["文学"],
  "我与地坛": ["文学", "哲学"],
  "瓦尔登湖": ["文学", "哲学"],
  "国富论": ["经济学"],
  "资本论": ["经济学"],
  "几何原本": ["数学", "自然科学"]
}
```

匹配规则：如果书名包含硬匹配表中的关键词，直接使用硬匹配标签，不再走关键词评分。

### 2.5 数据库现有标签修正

编写批量修正脚本，对数据库中已有的321本书重新运行优化后的标签分配算法，更新domain_tags字段。

## 三、实施步骤

### 步骤1：重构domain_tags.json关键词体系
- 将每个领域的关键词分为core/feature/general三级
- 清理跨领域污染词
- 为每个领域添加英文核心关键词
- 新增"数学"领域
- 建立书名硬匹配表

### 步骤2：优化DomainTagAssigner评分算法
- 实现加权关键词匹配（core=5.0, feature=2.0, general=0.5）
- 实现TF-IDF加权（基于数据库统计IDF值）
- 实现书名加权（3.0×书名 + 1.0×简介 + 0.5×作者简介）
- 实现置信度阈值过滤
- 实现领域排他性检查
- 实现英文文本检测和英文关键词匹配
- 实现书名硬匹配规则

### 步骤3：编写批量修正脚本
- 从数据库读取所有书籍数据
- 使用优化后的算法重新分配标签
- 输出修正前后的对比报告
- 确认无误后更新数据库

### 步骤4：验证与调优
- 检查之前标错的书籍是否被修正
- 检查之前标为"其他"的知名作品是否被正确标注
- 统计标签分布变化
- 根据验证结果微调关键词和参数
