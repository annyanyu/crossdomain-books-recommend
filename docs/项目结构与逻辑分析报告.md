## 三、模块依赖关系与数据流向

```

  ├── import: app.services.ranker.MultiObjectiveRanker

  ├── CrossDomainRecommender

  │     ├── 读取: MySQL数据库 books表 (embedding, keywords_embeddings, domain_tags)
  │     └── 输出: 推荐列表 [{book_id, title, final_score, ...}]
  │
  └── MultiObjectiveRanker
        ├── 依赖: datetime
        └── 输入/输出: 排序后的推荐列表
```

### 3.2 数据预处理流水线（离线执行）

```
步骤1: extract_keywords.py
  输入: 数据库 books表 (books_intro, author_intro)
  算法: jieba分词 → TF-IDF + TextRank → 融合排序
  输出: 更新 books.keywords 列

步骤2: assign_domain_tags.py
  输入: 数据库 books表 (title, book_intro, author_intro) + domain_tags.json
  算法: 关键词匹配计数 → 取top-2领域
  输出: 更新 books.domain_tags 列

步骤3: generate_embeddings.py
  输入: 数据库 books表 (title, book_intro, author_intro, short_reviews, reviews, reading_notes, keywords)
  算法: BAAI/bge-base-zh-v1.5 → 768维整体向量
        Word2Vec → 关键词向量列表
  输出: 更新 books.embedding 和 books.keywords_embeddings 列
```

## 四、核心业务逻辑与技术架构

### 4.1 核心业务：跨领域图书推荐

项目的核心创新点是**跨领域推荐算法**，其计算公式为：

```
FinalScore = CombinedSimilarity × OverlapCoefficient

其中:
  CombinedSimilarity = a × SemanticSimilarity + (1-a) × KeywordSimilarity
  KeywordSimilarity  = α × Sim_avg + (1-α) × Sim_max
  OverlapCoefficient = f(重叠标签数, β)
```

**参数配置**（来自 `backend/config.json`）：
- `α = 0.4`：关键词相似度中平均向量与最大匹配的权重
- `a = 0.6`：语义相似度与关键词相似度的权重
- `β = 0.25`：重叠标签惩罚系数

**跨域判定规则**：
- 重叠0个标签 → 系数1.0（完全跨域，不惩罚）
- 重叠1个标签 → 系数0.75
- 重叠2个标签 → 系数0.50
- 重叠3+个标签 → 系数0.0（同领域，完全过滤）

### 4.2 技术架构

```
┌──────────────────────────────────────────────┐
│                  前端层                        │
│  index.html + main.js + style.css            │
│  (原生JS, 无框架, Fetch API调用后端)            │
└───────────────┬──────────────────────────────┘
                │ HTTP REST API
┌───────────────▼──────────────────────────────┐
│                后端层                          │
│  Flask (app.py)                               │
│  ├── 路由层: 5个API端点                        │
│  ├── 服务层: app/services/                    │
│  │   ├── recommender.py (推荐计算)             │
│  │   └── ranker.py (多目标排序)                │
│  └── 配置层: config.json                      │
└───────────────┬──────────────────────────────┘
                │ SQLAlchemy + PyMySQL
┌───────────────▼──────────────────────────────┐
│               数据层                           │
│  MySQL (douban_books.books)                   │
│  核心字段: embedding, keywords_embeddings,     │
│           domain_tags, keywords, rating        │
└──────────────────────────────────────────────┘

离线预处理:
  algorithms/scripts/ → 生成向量/关键词/标签 → 写入数据库
```

### 4.3 实现流程

1. **数据准备**（离线）：运行 `extract_keywords.py` → `assign_domain_tags.py` → `generate_embeddings.py`，依次生成关键词、领域标签、语义向量，写入数据库
2. **服务启动**：`app.py` 启动时预加载推荐器，从数据库读取所有图书的向量数据到内存
3. **用户访问**：浏览器加载首页，JS调用 `/api/books` 获取图书列表
4. **推荐触发**：用户点击某本书，JS调用 `/api/recommend/:id?cross_domain=true`，后端实时计算相似度并返回跨域推荐
5. **排序展示**：推荐结果经 `MultiObjectiveRanker` 排序后返回前端渲染

## 五、关键组件与核心算法识别

### 5.1 关键组件

| 组件 | 位置 | 作用 |
|------|------|------|
| **推荐器** | `backend/app/services/recommender.py` | 运行时核心，加载全量向量数据到内存，实时计算余弦相似度 |
| **排序器** | `backend/app/services/ranker.py` | 对推荐结果按综合/评分/最新排序 |
| **配置文件** | `backend/config.json` | 集中管理数据库连接和算法超参 |
| **领域标签配置** | `algorithms/scripts/domain_tags.json` | 10个领域的200+关键词映射，是领域分类的依据 |

### 5.2 核心算法

1. **余弦相似度**（`backend/app/services/recommender.py` 第115-140行）：`cos(A,B) = (A·B) / (|A|×|B|)`，用于计算语义向量和关键词向量的相似度

2. **关键词相似度融合**（`backend/app/services/recommender.py` 第142-174行）：
   - `Sim_avg`：两本书关键词平均向量的余弦相似度
   - `Sim_max`：两本书关键词向量两两配对的最大余弦相似度
   - 融合：`α × Sim_avg + (1-α) × Sim_max`

3. **重叠标签系数**（`backend/app/services/recommender.py` 第192-220行）：基于领域标签重叠数量的阶梯惩罚函数

4. **TF-IDF + TextRank关键词提取**（`algorithms/scripts/extract_keywords.py`）：双算法融合，TF-IDF权重2倍于TextRank

5. **BAAI/bge-base-zh-v1.5向量生成**（`algorithms/scripts/generate_embeddings.py`）：768维中文语义向量，fallback为TF-IDF+SVD

### 5.3 重要设计特点

- **双版本架构**：`algorithms/` 下是算法参考实现（使用DataFrame、ConfigManager），`backend/app/services/` 下是运行时简化版（使用list、直接参数传入），两者算法逻辑一致但数据结构不同
- **单例缓存**：推荐器在 `app.py` 中以全局单例形式缓存，避免重复加载数据库
- **预加载机制**：服务启动时即加载全量图书向量数据到内存，牺牲内存换取实时推荐速度
- **空包预留**：`app/api/`、`app/models/`、`app/utils/` 为空包，为未来扩展预留
